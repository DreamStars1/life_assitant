# 待办 / 日程双视图 + 伴侣并排对比

## 背景

今日页与待办页目前以 Todo 列表为主：待办有完整 CRUD、指派与确认；今日页只展示近期未完成待办摘要。前端曾预留 `/events` 与 `events` API 契约，但后端无日程实体，页面为占位。

伴侣对比范式已在作息看板落地（双方查询 + 前端按 userId 对齐）。待办侧仅有「指派协作」，没有「看对方全部时间安排」的日/周对比。

目标：在**不新增底部 Tab**的前提下，把「待办页」和「今日页」做成 **待办 | 日程** 双视图；日程为带起止时间的时间块，支持日/周、只看自己 / 与伴侣并排对比，并支持向伴侣发起共同日程邀约。

## 决策摘要

| 项 | 选择 |
|----|------|
| 日程 vs 待办 | 独立域；时间块（start/end），非扩展 Todo |
| 入口 | `/todos` 与 `/` 页内一级 Tab「待办 \| 日程」；不升独立 Tab |
| 对比布局 | 日：左时间轴 + 右「我 \| TA」双栏；周：上我下 TA 双轨 |
| 伴侣权限 | 对方日程只读；可邀约共同日程（类似 Todo ack） |
| 邀约接受后 | 双方各持一份，`linkedEventId` 关联；之后改时间**不同步** |
| 重复 | 简单：`none` / `daily` / `weekly` + 可选结束日；读时展开，不物化 |
| 私密日程 | 第一版不做；绑定后互看全部日程 |
| 今日页日程 | 仅当日时间轴 + 只看我/两人；无周切换 |
| 旧 `/events` | 不作为入口；实现期删除或重定向到 `/todos` 日程视图 |

## 方案

采用 **独立日程域 + 页面内双 Tab**（相对「扩展 Todo kind」或「独立日程 Tab」）。

### 1. 导航与信息架构

底部 Tab 不变：今日 `/` · 待办 `/todos` · 伴侣 · 看板 · 我的。

**待办页 `/todos`**

- 一级：`待办 | 日程`（记住上次选中的一级）
- 待办：现有列表能力不变
- 日程二级：
  - 范围：`日 | 周`
  - 视角：`只看我 | 两人并排`（未绑定则**隐藏**「两人」，不展示置灰入口）
- 默认：日程为「日 + 只看我」

**今日页 `/`**

- 一级：`待办 | 日程`
- 待办：现有今日待办摘要
- 日程：仅当日时间轴；`只看我 | 两人`；**无**周切换（看周 → `/todos` 日程）

### 2. 数据模型

#### ScheduleEvent（新表，与 Todo 分离）

| 字段 | 说明 |
|------|------|
| id | PK |
| userId | 归属；创建者拥有，对方只读 |
| title | 必填 |
| startAt, endAt | 精确到分钟；`endAt > startAt` |
| note | 可选 |
| recurrence | `none` / `daily` / `weekly` |
| recurrenceEndDate | 可选；有重复时生效 |
| linkedEventId | 可选；共同邀约接受后指向对方镜像事件 |
| createdAt, updatedAt | 审计 |

第一版不做 `allDay`、不做单条「仅自己可见」。

**重复展开**：列表/日/周 API 按查询区间在**服务端**展开实例后返回；实例稳定键 `instanceKey = eventId + startAt`。第一版不支持「仅改此一次 / 此后续」——改系列 = 改整条规则。

#### ScheduleInvite（共同邀约）

| 字段 | 说明 |
|------|------|
| id | PK |
| sourceEventId | 发起方事件 |
| inviterUserId / inviteeUserId | 双方 |
| status | `pending` / `accepted` / `rejected` |
| createdAt, respondedAt | 审计 |

接受后：在 invitee 名下创建镜像 `ScheduleEvent`（同标题与起止），双方 `linkedEventId` 互指；拒绝则仅发起方保留原事件。接受后任一方改时间/删除**不**自动同步到另一方（明确简化；若以后要同步，在关联上扩展，而非默认同步）。

补充规则：同一事件同时最多一条 `pending` 邀约；删除发起方事件时取消其 pending 邀约；已接受的镜像对删除一侧只删该用户副本，另一侧保留且清空其 `linkedEventId`。

### 3. API（草案）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/schedule/events?from&to` | 自己的事件（区间内展开） |
| GET | `/schedule/events/partner?from&to` | 伴侣只读；需已绑定 |
| POST | `/schedule/events` | 创建 |
| PATCH | `/schedule/events/{id}` | 更新（仅自己的） |
| DELETE | `/schedule/events/{id}` | 删除（仅自己的） |
| POST | `/schedule/events/{id}/invite` | 向伴侣发起共同邀约 |
| POST | `/schedule/invites/{id}/acknowledge` | accept / reject |

查询区间建议硬上限（如最多 62 天），避免一次展开过大。

路径前缀跟现有 Controller 惯例（与 `/todos`、`/partner/*` 同级风格），实现计划里写死具体前缀，本文不双轨。

### 4. 前端视图与交互

**日 · 只看我**
左小时轴 + 单列事件块。点空白新建；点块 → 详情（编辑/删除/发起共同邀约）。

**日 · 两人（布局 A）**
左小时轴 · 右「我 | TA」双栏对齐。TA 列只读；pending 邀约角标。点 TA 块仅详情。

**周 · 只看我**
与两人周同构，仅显示上轨（我），避免两套周组件。

**周 · 两人（W2）**
上轨我、下轨 TA，各 7 天摘要/条带。偏「哪天有事」；点某天 → 进入该日的日视图两人模式，做小时级对齐。

**今日页日程**
复用日视图组件（当日 + 只看我/两人）。

**表单字段**
标题、起止、备注、重复（无/每天/每周 + 可选结束日）。

### 5. 权限与错误

- 只能改删自己的事件；伴侣事件只读
- 未绑定：禁止 partner 查询与邀约；前端隐藏「两人」
- 邀约仅对已绑定伴侣；acknowledge 仅 invitee
- 校验：标题非空、`endAt > startAt`、重复枚举、`recurrenceEndDate`（若有）合理
- 未绑定/解绑后调 partner API：明确错误码，前端回退「只看我」
- 空栏：空态文案，不报错

### 6. 测试要点

1. daily/weekly 在日/周区间展开正确、不越界
2. 绑定后日双栏、周双轨数据按 userId 对齐
3. 邀约 pending → accept 出镜像；reject 无镜像；接受后改一侧不同步
4. 未绑定不能拉 partner、不能 invite
5. 今日页日程仅当天，且可切两人

### 7. 非目标（第一版不做）

- 私密日程、全天事件、复杂重复（工作日/自定义间隔）
- 「仅此一次」编辑、接受后双向时间同步
- 独立底部「日程」Tab、冲突自动检测/建议空档
- 把 Todo 与 Schedule 合成统一时间轴（今日页仍分 Tab）

## 架构关系（简图）

```
[/] 今日          [/todos] 待办页
  ├ 待办摘要         ├ 待办列表（现有）
  └ 日程(当日)       └ 日程(日|周)
         │                  │
         └──── Schedule API ┘
                ├ own events
                ├ partner events (readonly)
                └ invites (ack → linked pair)
```

复用现有 `partnerId` 绑定与 Todo 邀约确认的交互心智；数据对齐方式对齐作息看板的双方拉取模式。
