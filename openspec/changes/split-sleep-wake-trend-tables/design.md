## Context

作息详情页 `sleep.vue` 当前用一张 ECharts 折线图同时画起床/睡觉（我方 + 伴侣共 4 条线），数据来自 `GET /partner/checkin/weekly`（固定近 7 个业务日）。看板主页有同逻辑的缩略图，点击进入详情。

Mapper 的 `findWeekly(startDate)` 已是「`checkin_date >= startDate`」，扩展到 30 天只需改 start 计算与入参校验，无需改表结构。

## Goals / Non-Goals

**Goals:**

- 详情页拆成两张独立走势图：起床、睡觉（各含我方与伴侣）
- 提供 7 天 / 30 天筛选，切换后两图同步刷新
- 后端支持按 7 / 30 天查询双方打卡记录（业务日仍以凌晨 4 点为界）

**Non-Goals:**

- 不改打卡写入 / 今日打卡逻辑
- 看板主页不做 7/30 筛选（仅近 7 天分图预览）
- 不做自定义日期区间、不做统计均值/达标率卡片
- 不引入新图表库或新依赖

## Decisions

### 1. 「表格」落地为两张走势图卡片，不是数据表

- **选择**：继续用 ECharts 折线图，拆成「起床走势」「睡觉走势」两张卡片。
- **原因**：现有能力是走势分析；用户口语「表格」在此语境对应分块展示。真做 HTML 表格会丢失趋势可读性。
- **备选**：下方再加数字表 —— 本期不做（YAGNI）。

### 2. 筛选 UI：同一控件管两张图

- **选择**：走势区上方一个 `van-tabs` / 分段按钮（7 天 | 30 天），状态 `rangeDays: 7 | 30`，两图共用。
- **原因**：起床/睡觉分筛意义不大，且多一次请求。
- **备选**：每图各自筛 —— 拒绝（交互重复）。

### 3. API：在现有 weekly 上加 `days` 查询参数

- **选择**：`GET /partner/checkin/weekly?days=7|30`，默认 `7`；非法值返回 400。Service：`start = end.minusDays(days - 1)`，仍走 `findWeekly`。
- **原因**：Mapper 已按 startDate 过滤；看板不传参行为不变；改动面最小。
- **备选**：新 `/range` 并弃用 weekly —— 多一层无必要别名。

### 4. 前端数据与图表重建

- **选择**：切换 `rangeDays` 时重新请求并 `dispose` + 重建两个 chart 实例；X 轴长度 = `rangeDays`；30 天时 `axisLabel.interval` 抽稀，避免挤爆。
- **原因**：两图生命周期简单，避免一套 option 里藏四条线再 legend 过滤。
- **起床图 Y 轴**：继续用分钟数（wake 不跨日加 1440）；可收紧到常见起床窗口（如 300–720），缺省点仍为 null。
- **睡觉图 Y 轴**：sleep 且 `h < 12` 仍 `+1440`；窗口保持偏晚到次日清晨（如 1080–1620）。

### 5. 看板主页同步分图，不做天数筛选

- **选择**：`index.vue` 近 7 天缩略图拆成起床 / 睡觉两张卡片，均跳转详情；不放 7/30 筛选。
- **原因**：与详情页视觉一致；筛选只在详情页需要。
- **备选**：主页也加筛选 —— 拒绝（卡片过高）。

## Risks / Trade-offs

- [30 天 X 轴拥挤] → 标签抽稀 + 固定图高；tooltip 仍显示完整日期与时间
- [非法 days 被滥用] → 后端白名单仅 7、30
- [两图双实例内存] → `onUnmounted` 统一 dispose；页面为轻量详情页可接受
- [用户其实要数字表] → 若反馈明确再加；本期按走势图交付

## Migration Plan

1. 先发后端 `days` 参数（默认 7，兼容旧客户端）
2. 再发前端详情页分图 + 筛选
3. 回滚：前端回退即可；后端保留 `days` 无害
